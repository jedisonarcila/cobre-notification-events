Diseño · flujo de procesamiento

El recorrido de un evento

Matching

El evento entra por la cola; el matcher genera una entrega por cada suscripción activa del cliente.

Idempotencia

id = hash(event_id + subscription_id): reprocesar no reentrega. Efecto exactly-once sobre transporte at-least-once.

Tres resultados

Completed y failed son terminales; transient reencola con backoff e incrementa el intento.

La espera vive en la cola

El reintento no bloquea el proceso: se difiere en la cola. Un reinicio no pierde ni retrasa entregas.

Broker durable + matching

El enrutamiento no se delega a filtros del broker. La tabla de suscripciones es la fuente de verdad; el matcher la consulta por evento.

Reintentos: backoff + jitter

La espera vive en la cola, no en el proceso. Un reinicio no pierde reintentos. Solo se reintentan fallos transitorios (timeout, 5xx, 429).

Idempotencia determinista

id = hash(event_id + subscription_id). Reprocesar no reentrega: exactly-once de efecto sobre transporte at-least-once.

Un solo resultado por evento

El almacén guarda el resultado terminal; lo en-vuelo vive en la cola. No se duplican escrituras por estados intermedios.

Implementación · hexagonal + despliegue en red

Dos servicios, un núcleo, red aislada

Núcleo sin nube

El dominio no conoce Spring ni AWS: depende de puertos. Delivery y API comparten núcleo; cambia el adaptador de entrada (SQS vs HTTP).

Backend privado

Las tareas Fargate viven en subredes privadas. El API Gateway las alcanza vía VPC Link + ALB interno; el egreso sale por NAT (anti-SSRF).

Seguridad · OWASP Top 10

Cuatro amenazas, cuatro mitigaciones

A01 · BOLA / IDOR
Acceso entre clientes
Aislamiento estructural. El client_id se deriva del token, jamás del path o body. Es la partition key en DynamoDB: una consulta nunca trae datos de otro tenant. Recursos ajenos → 404.
SSRF
URL de webhook maliciosa
Validación de la URL + egreso aislado. Al registrarla se valida el esquema (solo https, nada de http, file://, gopher://) y se rechazan IPs privadas o link-local, incluida la metadata 169.254.169.254. Como respaldo, el worker corre en subred privada; Fargate además aísla las credenciales por tarea.
A07 · Auth
Fallos de autenticación
Doble capa. El borde (API Gateway) valida el token con Cognito; el núcleo (Spring Security) verifica la firma del token localmente con las llaves públicas de Cognito, guardadas en memoria. WAF con límite de intentos contra fuerza bruta.
A09 · Logging
Observabilidad insuficiente
Registro near-real-time. Métricas EMF a CloudWatch, dashboards en Grafana, alertas sobre 401/403 y desviación de fallo. Redacción de PII y secretos en logs.
Decisiones clave · costo-eficiencia

Trade-offs que sostienen el diseño

SNS

Eliminado. El productor publica directo a la cola. Se inserta si se necesita fan-out, sin tocar el origen.

Store

Solo DynamoDB. Point-lookup por client_id, aislamiento gratis, escala a cero. Sin caché para no arriesgar correctitud.

Filtro

GSI, no scan. client_id#status da consulta directa sobre tablas de miles de millones de registros.

Cómputo

ECS Fargate. Escala con baja administración. Gateway → backend privado vía VPC Link + ALB interno.

Observab.

CloudWatch + Grafana. Base near-real-time en-stack; Datadog descartado por costo (~10×).

HA

2 AZ. Cómputo replicado; SQS y DynamoDB son regionales multi-AZ. Un NAT por AZ.
